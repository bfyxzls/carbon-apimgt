# WSO2 APIM JWT Bearer Token用户生成OAuth Keys失败修复方案

## 问题根源

通过JWT Bearer方式登录的用户，在调用`/applications/<app_id>/generate-keys`接口时，Key Manager返回500错误，导致`consumer_key`为空。

**根本原因：**
1. 在`ApplicationsApiServiceImpl.applicationsApplicationIdGenerateKeysPost`方法中，使用`RestApiCommonUtil.getLoggedInUsername()`获取用户名
2. 对于JWT Bearer token登录的用户，这个用户名可能：
   - 格式不正确（缺少tenant domain）
   - 在Key Manager中不存在
   - 没有创建OAuth应用的权限

## 解决方案

### 方案1：使用应用所有者（Subscriber）作为OAuth应用所有者（推荐）

修改`ApplicationsApiServiceImpl.applicationsApplicationIdGenerateKeysPost`方法，使用应用的所有者（subscriber）而不是当前登录用户作为OAuth应用的所有者。

**修改位置：** `components/apimgt/org.wso2.carbon.apimgt.rest.api.store.v1/src/main/java/org/wso2/carbon/apimgt/rest/api/store/v1/impl/ApplicationsApiServiceImpl.java`

**修改内容：**

```java
// 第880行，将：
jsonParamObj.put(ApplicationConstants.OAUTH_CLIENT_USERNAME, username);

// 改为：
// 使用应用的所有者（subscriber）作为OAuth应用的所有者
// 这样可以确保OAuth应用在正确的用户上下文中创建
String oauthClientUsername = application.getSubscriber().getName();
// 如果应用是组织共享的，使用当前用户
if (application.getSharedOrganization() != null && 
    !APIConstants.DEFAULT_APP_SHARING_KEYWORD.equals(application.getSharedOrganization())) {
    oauthClientUsername = username;
}
jsonParamObj.put(ApplicationConstants.OAUTH_CLIENT_USERNAME, oauthClientUsername);
```

### 方案2：配置Key Manager使用管理员作为应用所有者

如果配置了`kmAdminAsAppOwner`，Key Manager会使用管理员用户作为OAuth应用的所有者。这可以避免用户权限问题。

**配置位置：** Key Manager配置中设置`kmAdminAsAppOwner=true`

**优点：**
- 不需要修改代码
- 统一使用管理员权限创建OAuth应用

**缺点：**
- 所有OAuth应用都使用管理员作为所有者，可能不符合某些安全要求

### 方案3：确保JWT Bearer用户格式正确

确保通过JWT Bearer登录的用户名包含正确的tenant domain格式。

**修改位置：** `components/apimgt/org.wso2.carbon.apimgt.rest.api.store.v1/src/main/java/org/wso2/carbon/apimgt/rest/api/store/v1/impl/ApplicationsApiServiceImpl.java`

**修改内容：**

```java
// 第863行，获取用户名后，确保格式正确
String username = RestApiCommonUtil.getLoggedInUsername();
String tenantDomain = RestApiCommonUtil.getLoggedInUserTenantDomain();

// 确保用户名包含tenant domain（如果不是super tenant）
if (!MultitenantConstants.SUPER_TENANT_DOMAIN_NAME.equals(tenantDomain)) {
    if (!username.contains(UserCoreConstants.DOMAIN_SEPARATOR)) {
        username = username + UserCoreConstants.DOMAIN_SEPARATOR + tenantDomain;
    }
}

// 第880行使用格式化后的用户名
jsonParamObj.put(ApplicationConstants.OAUTH_CLIENT_USERNAME, username);
```

## 推荐实施步骤

1. **首先实施方案1**：使用应用所有者作为OAuth应用所有者，这是最符合业务逻辑的方案
2. **然后实施方案4**：改进错误处理，确保数据一致性
3. **如果方案1不适用**，考虑方案2（配置kmAdminAsAppOwner）或方案3（确保用户名格式正确）

## 测试验证

修复后，需要验证：
1. 通过JWT Bearer token登录的用户可以成功生成OAuth keys
2. `am_application_key_mapping`表中的`consumer_key`字段正确填充
3. 如果OAuth应用创建失败，数据库状态保持一致（记录被标记为失败或回滚）

## 注意事项

1. 如果使用方案1，需要确保应用的所有者（subscriber）在Key Manager中存在并有创建OAuth应用的权限
2. 如果使用方案2，需要确保Key Manager管理员用户配置正确
3. 所有修改都需要在测试环境充分测试后再部署到生产环境
